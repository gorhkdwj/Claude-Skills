### 부분적 배경정보 처리

배경정보의 일부만 제공할 수 있는 경우:
- 사용 가능한 정보로 진행하고 제한 사항을 기록하겠습니다
- 적절한 경우 업계 표준 기본값을 사용하겠습니다
- 분석 중에 필요한 대로 명확한 질문을 하겠습니다

## 워크플로우

### 단계 1: 배경정보 검증

시작하기 전에 다음을 확인하겠습니다:
- [ ] 필요한 모든 배경정보가 이용 가능하거나 합리적인 기본값이 있는가
- [ ] 범위와 목표가 명확한가
- [ ] 예상 결과물이 귀사의 요구사항에 부합하는가

### 단계 2: 핵심 분석 실행

방법론 설명자의 모범 사례를 따르면서:

1. **초기 평가** - 제공된 배경정보와 데이터 검토
2. **체계적 실행** - 구조화된 방법론 따르기
3. **품질 검사** - 중간 결과 검증
4. **단계별 공개** - 논리적 체크포인트에서 결과 공유

### 단계 3: 결과 종합

명확하고 실행 가능한 형식으로 결과를 제시하겠습니다:
- 중요도별로 우선순위가 지정된 핵심 발견사항
- 지원 증거 및 시각화
- 구현 지침이 포함된 권장사항
- 문서화된 제한사항 및 가정

### 단계 4: 피드백에 따라 반복

초기 결과를 제시한 후:
- 필요한 경우 질문에 답하고 더 깊이 파고들기
- 귀사의 피드백에 따라 분석 개선
- 추가 배경정보 또는 대체 접근방식 제공

## 배경정보 검증

전체 워크플로우를 실행하기 전에 다음을 확인합니다:

- [ ] 의미 있는 분석을 위해 배경정보가 충분한가
- [ ] 제공된 정보에 모순이 없는가
- [ ] 범위가 명확하고 달성 가능한가
- [ ] 예상 결과물이 명확한가

## 일반적인 배경정보 누락 및 해결 방안

**시나리오: 사용자가 배경정보를 제공하지 않고 방법론 설명자를 요청**
→ 응답: "방법론 설명자를 도와드릴 수 있습니다! 가장 관련성 높은 분석을 제공하려면 [핵심 배경정보]가 필요합니다. [구체적 요청]을 공유해주실 수 있을까요?"

**시나리오: 부분적 배경정보가 제공됨**
→ 응답: "[사용 가능한 배경정보]가 있습니다. [가능한 작업]으로 진행하겠으며 추가 배경정보가 분석을 개선할 수 있는 부분을 기록하겠습니다."

**시나리오: 목표가 불명확함**
→ 응답: "귀사의 요구사항을 충족하는 분석을 위해 명확히 해주실 수 있을까요: 이 분석이 어떤 결정에 영향을 미칠까요? 어떤 형식이 가장 유용할까요?"

**시나리오: 도메인별 용어**
→ 응답: "귀사의 용어를 올바르게 이해하고 있는지 확인하고 싶습니다. [용어]라고 말씀하실 때, [해석]을 의미하시나요?"
